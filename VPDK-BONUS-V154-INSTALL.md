# VPDK Bonus V154: одна таблиця + проекції 100%

## Що змінено

V154 **повністю прибирає стару Google-таблицю з активної логіки**. Єдине джерело даних:

- `SPREADSHEET_ID = 1J6pgu1HEuufkSA_O3EpcMwrylenAg685sQH4lRMjAic`
- таблиця: **«Електронна таблиця без назви»**

У цій самій таблиці тепер працюють:

- усі звітні вкладки;
- `Schedule`;
- прихований кеш `_TM6_REPORT_CACHE`;
- службова вкладка `_TM6_TEAM_MESSAGES`.

Старий ID таблиці у робочому `Code.gs` більше не використовується.

## Goals видалено з логіки

V154 більше не:

- шукає вкладку `Goals`;
- читає рядки цілей;
- записує `credit_target`, `debit_target`, `deposit_target` у Google Sheets;
- використовує місячну бонусну ціль;
- дозволяє адміністратору вручну редагувати персональні цілі.

Для сумісності зі старими API деякі поля все ще називаються `goals`, але це лише **read-only alias проекцій**. Дані для них будуються автоматично зі звітних вкладок, а не з листа `Goals`.

## Нова логіка «Мої проекції»

Для кожного оператора показується його фактична проекція зі звіту, а ціль завжди фіксована:

- Credit → проекція з `Credit`, ціль **100%**;
- Debit → проекція з `Debit`, ціль **100%**;
- Deposit → проекція з видимого `Deposit `, ціль **100%**;
- Activation Deb / ПУМБ Online → проекція, ціль **100%**;
- Activation CC / картки → проекція, ціль **100%**.

Сторінка «Мої цілі» перейменована в «Мої проекції». Блоки тижневих нагород і місячної бонусної цілі прибрані. В адмінці вкладка «Цілі» перейменована в «Проекції» і стала read-only.

## Schedule

`Schedule` читається з нової таблиці. Поточний формат підтримується:

- рядок 1: `Логін`, `ставка`, `1 ... 31`;
- рядок 2: дні тижня (`сб`, `нд`, `пн` ...);
- нижче: зміни операторів (`9-18`, `9-16`, `11-20`, `10-19`, `В`, `Відпустка`).

Парсер використовує другий рядок з днями тижня, щоб правильно визначити місяць/дати.

## Важливий нюанс Deposit

У поточній таблиці є:

- видимий аркуш `Deposit ` із пробілом наприкінці;
- прихований допоміжний аркуш `Deposit`.

V154 шукає аркуші за нормалізованою назвою та **віддає пріоритет видимому аркушу**, тому депозитна проекція береться саме з `Deposit `.

## Як встановити без старої таблиці

1. Відкрий **нову** таблицю «Електронна таблиця без назви».
2. Відкрий **Розширення → Apps Script** саме з нової таблиці.
3. Замінити `Code.gs` файлом `integrations/google-sheets/Code.gs` із V154.
4. Перенести Script Properties, які використовує застосунок, зокрема `WRITE_TOKEN`, `VPDK_BACKEND_URL`, `REPORTS_WEBHOOK_TOKEN` та інші потрібні секрети.
5. Якщо Web App був розгорнутий зі старого Apps Script-проєкту, створити/оновити deployment нового Apps Script і оновити `GOOGLE_GOALS_SCRIPT_URL` у Netlify.
6. Запустити `refreshReports()` або в новій таблиці натиснути **Звіти → Оновити звіти**.
7. Після першого запуску в новій таблиці автоматично створиться прихований `_TM6_REPORT_CACHE`; `_TM6_TEAM_MESSAGES` створиться при першому використанні повідомлень.

Після цього старий Google Sheets-файл для роботи застосунку не потрібен.

## Перевірка

```bash
node test_report_source_v153.js
node test_report_source_v154.js
node test_google_goals_integration.js
```

`test_report_source_v154.js` додатково перевіряє:

- відсутність старого spreadsheet ID у робочому `Code.gs`;
- роботу без аркуша `Goals`;
- фіксовану ціль 100% для всіх проекцій;
- пріоритет видимого `Deposit ` над прихованим `Deposit`;
- читання `Schedule` з дворядковою шапкою;
- формування повного snapshot без старої таблиці.

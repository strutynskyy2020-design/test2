# VPDK Bonus v126: збереження типу звітів

## Причина

У v125 адмін-форма показувала повідомлення «Оновлено» одразу після успішного PATCH-запиту. Якщо на сервері залишався старий backend, Pydantic ігнорував невідоме поле `report_profile`, повертав HTTP 200, а тип користувача фактично лишався `sales`. Додатково активна сесія оператора перевіряла `/auth/me`, але не записувала свіжого користувача у React state, а IndexedDB продовжував віддавати старий звітний профіль.

## Виправлення

- Додано окремий перевірюваний endpoint `PATCH /api/admin/users/{user_id}/report-profile`.
- Загальний endpoint також перевіряє, що MongoDB справді зберегла `report_profile`.
- Адмінка порівнює запитаний тип із відповіддю сервера і більше не показує хибне «Оновлено».
- Сесія оператора раз на хвилину застосовує свіжі дані `/auth/me`.
- При зміні типу, Google-логіна, команди або ролі очищається кеш звітів і завантажується правильний профіль.
- Ключ IndexedDB тепер включає `report_profile`, `goals_login`, команду та права доступу.
- Service Worker і кеш звітів піднято до v126.

## Розгортання

Потрібно оновити **backend і frontend/Netlify одночасно**. Google Apps Script v125 можна залишити без змін, бо помилка не стосується парсерів таблиці.

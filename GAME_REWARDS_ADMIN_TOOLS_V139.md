# Game rewards and admin tools v139

## 1. Bonus Match

```text
Перше проходження рівня: +2 Point, +10 XP
Повторне проходження:     +0 Point, +5 XP
```

Нагорода зберігається на рівні backend і дублюється у frontend-fallback для офлайн/помилкового сценарію.

## 2. VPDK Sudoku

```text
Перше проходження рівня: +2 Point, +10 XP
Повторне проходження:     +0 Point, +5 XP
```

Логіка ідемпотентності сесії та відкриття наступних рівнів не змінювалася.

## 3. AI-тренажер

Point-нагорода більше не залежить від складності кейсу. Використовується перевірена середня оцінка:

```text
менше 5 → 0 Point
5        → 5 Point
6        → 6 Point
7        → 7 Point
8        → 8 Point
9        → 9 Point
10       → 10 Point
```

Дробова середня оцінка округлюється до найближчого цілого в межах 5–10.

Нагорода видається лише за перше успішне проходження конкретного `scenario_id`. Повторні спроби зберігаються у статистиці та можуть давати XP, але Point дорівнюють нулю.

Для захисту від подвійного нарахування використовується окрема колекція `ai_training_completions` з унікальним ключем:

```text
user_id + scenario_id
```

Історичні успішні результати автоматично позначаються як завершені без додаткового нарахування.

## 4. Щедрий куб

Перший кидок за київську добу залишається безкоштовним. Кожен наступний коштує `20 Point`.

| Грань | Діапазон виграшу |
|---|---:|
| 1 | 1–10 Point |
| 2 | 11–20 Point |
| 3 | 21–30 Point |
| 4 | 31–50 Point |
| 5 | 51–100 Point |
| 6 | 101–500 Point |

Ймовірності граней не змінювалися.

## 5. Адмін-панель

### Юзери

Пошук фільтрує за:

- ім’ям;
- email;
- посадою та відділом;
- командою;
- логіном Google-цілей.

Командний фільтр і пошук працюють одночасно.

### Бали та баланс

Додано такий самий пошук співробітників і швидкі нарахування:

```text
+10  +20  +30  +40  +50
```

Кнопки використовують чинний endpoint ручного нарахування, тому транзакція потрапляє в історію балансу та сповіщення.

# VPDK Bonus v114: встановлення

## Що входить у v114

- єдиний **Центр сповіщень** у дзвіночку шапки;
- PWA Web Push для важливих подій;
- автоматичні щоденні нагадування за київським часом:
  - 09:00: початок робочого дня;
  - 12:00, 15:00, 17:00: оновлення таблички видач;
- Push-події для нових Point, досягнень, призів, статусів замовлень, повідомлень керівника, оновлених звітів, нових рівнів і змін позиції в рейтингу;
- персональні налаштування категорій Push;
- тестове Push-сповіщення з інтерфейсу;
- окрема сторінка **«Аналітика команди»** для керівника й адміністратора;
- тренди активності, Point, ігор, звітів і порівняння команд;
- Google Apps Script повідомляє backend після натискання **«Оновити звіти»**;
- Service Worker оновлено до `vpdk-v114`.

## 1. Backend

Розгорніть папку `backend` разом з оновленим `requirements.txt`.

Додайте змінні середовища:

```env
VAPID_PUBLIC_KEY=<public key>
VAPID_PRIVATE_KEY=<private key>
VAPID_SUBJECT=mailto:admin@callhub.ua
PUSH_SCHEDULER_TOKEN=<long random secret>
REPORTS_WEBHOOK_TOKEN=<another long random secret>
```

Згенерувати VAPID-ключі можна одноразово:

```bash
npx web-push generate-vapid-keys
```

`VAPID_PRIVATE_KEY`, `PUSH_SCHEDULER_TOKEN` і `REPORTS_WEBHOOK_TOKEN` є секретами. Не додавайте їх у Git або frontend.

## 2. Netlify

Розгорніть `frontend` і `netlify/functions`.

У Netlify додайте:

```env
BACKEND_URL=https://your-backend.example.com
PUSH_SCHEDULER_TOKEN=<те саме значення, що на backend>
```

`BACKEND_URL` має бути без `/api` наприкінці.

Функція `push-scheduler.mjs` запускається щогодини. Backend сам визначає час `Europe/Kyiv`, тому літній і зимовий час не треба перераховувати вручну.

Після deployment перевірте в Netlify, що Scheduled Function **push-scheduler** з’явилася у списку функцій.

## 3. Google Apps Script

Замініть поточний код файлом:

```text
integrations/google-sheets/Code-v114.gs
```

У Apps Script відкрийте **Project Settings → Script properties** і додайте:

```text
VPDK_BACKEND_URL = https://your-backend.example.com
REPORTS_WEBHOOK_TOKEN = те саме значення, що на backend
```

Створіть нову версію Web App:

```text
Deploy → Manage deployments → Edit → New version → Deploy
```

Для кнопки в Google Таблиці функція залишається без змін:

```text
refreshReports
```

Після натискання кнопки Apps Script:

1. створює новий snapshot;
2. зберігає його в `_TM6_REPORT_CACHE`;
3. надсилає backend версію та командні підсумки;
4. backend створює сповіщення **«Звіти оновлено»** і записує точку для графіка кредитного/дебетового тренду.

Якщо webhook тимчасово недоступний, snapshot у Google Таблиці все одно збережеться. Помилка webhook не зламає кнопку.

## 4. Увімкнення Push користувачем

Браузери дозволяють запитувати дозвіл лише після дії користувача.

1. Відкрийте дзвіночок у шапці.
2. Перейдіть у вкладку **Push**.
3. Натисніть **«Увімкнути Push»**.
4. Підтвердьте системний дозвіл.
5. Натисніть **«Надіслати тест»**.

У цій самій вкладці можна окремо вимкнути робочі нагадування, рейтинги, ігрові події або інші категорії.

## 5. Аналітика керівника

Користувач повинен мати:

- `is_team_leader = true`, або
- роль `admin`.

Відкрийте **Команди → Аналітика команди**.

Доступні періоди: день, тиждень і місяць. Адміністратор може перемикати команду або переглядати загальний зріз.

## 6. Оновлення PWA

Після deployment:

1. повністю закрийте PWA;
2. відкрийте її повторно;
3. за потреби перезавантажте ще раз, щоб активувався `vpdk-v114`;
4. стару Push-підписку повторно створювати не потрібно, якщо браузер її зберіг.

## 7. Швидка перевірка

- Backend `/api/health` відповідає `ok`.
- У дзвіночку відкривається центр сповіщень.
- У вкладці Push відправляється тест.
- Netlify викликає `push-scheduler` щогодини.
- Натискання **«Оновити звіти»** створює сповіщення.
- Керівник відкриває `/analytics` і бачить свою команду.

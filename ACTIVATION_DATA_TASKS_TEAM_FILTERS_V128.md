# VPDK Bonus v128: ПУМБ Online, завдання активаторів і фільтр команд

## 1. Виправлення звіту ПУМБ Online

Попередня логіка могла поєднати дані з різних блоків Google Таблиці:

- особисті місячні показники оператора;
- командний або загальний підсумок іншого періоду;
- видачі за вчора замість видач за місяць.

Через це на сторінці `dzhunuso` проекція `121%` була правильною, але поруч могли з'являтися `324`, `00:01:38`, `45099` і `27`, які належали іншим колонкам або періодам.

У v128 кожен особистий рядок отримує зв'язаний підсумок за ключем:

```text
логін + період + команда
```

Google Apps Script додає до персонального рядка `team_summary`, `*_team` і `team_overall`. Netlify gateway додатково відсікає сторонні логіни й рядки іншого періоду. Frontend спочатку використовує ці точні поля, а загальні масиви залишає лише резервним джерелом.

Контрольний місячний набір для `dzhunuso`:

| Показник | Особистий | TM7 |
|---|---:|---:|
| Проекція | 121% | 101,60% |
| Оброблено | 1024 | 21350 |
| AHT | 00:02:54 | 00:01:47 |
| Рівень згод | 68% | 66% |
| Виконано | 50% | 48% |
| Активації від згод | 36,1% | 32,1% |
| ПУМБ Online від оброблених | 31,84% | 26,64% |
| Видачі | 318 | 5371 |

## 2. Окремі завдання для активаторів

Каталоги продажників та активаторів тепер розділені. Тип каталогу визначається полем користувача `report_profile`.

- `sales` — чинні завдання продажників;
- `activation` — 30 нових завдань активаторів, по 10 на кожну складність.

ID активаторських завдань винесені в окремий діапазон `1001–1030`, тому старі заявки, перевірки й історія продажників не перетинаються з новими завданнями.

Документ щоденного набору зберігає:

```text
catalog_profile
catalog_version
```

Якщо адміністратор змінює тип оператора, система не залишає йому старий набір до наступного дня, а перебудовує його під правильний каталог.

## 3. Фільтр команд у всіх вкладках адмінки

У контейнер адмін-панелі додано один глобальний `teamFilter`. Значення зберігається в `localStorage`, тому не скидається при переході між вкладками.

Для великих наборів даних фільтр передається на backend через `team_id`:

- огляд та аналітика;
- AI-команда;
- завдання дня;
- цілі;
- досягнення;
- заявки;
- замовлення.

Для вже завантажених локальних списків фільтрація виконується у frontend:

- користувачі;
- команди;
- бали та баланс;
- модерація;
- призи;
- банки команд.

Історичні заявки та замовлення без збереженого `team_id` отримують команду з профілю автора під час читання, тому старі записи також потрапляють у правильний фільтр.

## 4. Сумісність

- Базова версія: **v126**.
- Профілі продажників, кредитні, дебетові та депозитні звіти не змінені.
- Сегменти видач карток `A`, `B`, `C`, `D` збережені.
- Поведінка п'ятихвилинного кешу v126 збережена навмисно.
- Зміни v127 не включені.

# Алмазні аватари у стрічці активності — v136

## Backend

Додано окремий тип події:

```text
kind: diamond_avatar
```

Під час виконання:

```text
POST /api/admin/users/{user_id}/diamond-avatar
```

backend зберігає документ у колекції `feed_events`. У ньому фіксуються:

```text
user_id
user_name
avatar_url
avatar_rarity = diamond
avatar_code
duration_days = 3
daily_bonus = 100
task_replacements = 5
expires_at
created_at
```

Портрет і рідкісність записуються як знімок на момент видачі. Це потрібно, щоб після автоматичного повернення попереднього аватара стара подія й надалі показувала саме видану нагороду.

Для `feed_events` створюються індекси за `id`, `source_key` і `created_at`. `source_key` захищає стартове перенесення активних нагород від дублювання.

Функція `_backfill_active_diamond_feed_events_v136()` один раз додає події для активних алмазних аватарів, виданих до v136.

Метод `_feed_event_owner()` тепер розпізнає власника подій із `feed_events`, тому реакції й коментарі надсилають правильні сповіщення працівнику.

## Frontend

`FeedItem` отримав окремий стиль для `diamond_avatar`:

- іконка діаманта;
- кристалічний синьо-фіолетовий фон;
- анімований відблиск і повільна аурора;
- позначка «Особлива нагорода адміністратора»;
- чипи `+100 Point щодня`, `+5 замін`, `3 дні`;
- справжній `AvatarFrame` із `avatar_rarity="diamond"`.

Анімації вимикаються через `prefers-reduced-motion` для користувачів, які обрали зменшення руху в системі.

У `/feed` додано фільтр **«Алмазні»**. Та сама преміальна картка автоматично відображається у короткій стрічці на головній сторінці.

# VPDK Bonus v150 — денна історія звітів оператора

## Нова модель зберігання

Замість окремого MongoDB документа для кожного `snapshot_version + report_type + period + segment` використовується один документ на працівника на календарний день за часовим поясом `Europe/Kyiv`.

Приклад структури:

```json
{
  "user_id": "...",
  "date_key": "2026-08-13",
  "reports": {
    "credit": {
      "month": {
        "xsell": { "metrics": [ ... ] },
        "web_apps": { "metrics": [ ... ] },
        "inb": { "metrics": [ ... ] }
      }
    },
    "deposit": {
      "month": {
        "overall": { "metrics": [ ... ] }
      }
    },
    "activation_pumb": {
      "month": {
        "overall": { "metrics": [ ... ] }
      }
    },
    "activation_cards": {
      "month": {
        "overall": { "metrics": [ ... ] }
      }
    },
    "debit": {
      "month": {
        "overall": { "metrics": [ ... ] }
      }
    }
  }
}
```

## Кілька оновлень за день

Якщо Google-звіти оновили 2, 3 або більше разів протягом одного дня, MongoDB не створює нові документи для кожної години.

Оновлюється відповідна вкладена секція в документі поточного дня. Тому:

- у MongoDB залишається один документ `user_id + date_key`;
- у графіку один календарний день показується рівно один раз;
- значення дня — останнє збережене значення після останнього оновлення цього дня.

## Індекси

Додано унікальний індекс:

`(user_id, date_key)`

Це додатково гарантує, що для одного працівника неможливо створити два денних документи з однаковою датою.

## Старі v149 записи

Нова версія більше не записує дані у `operator_report_snapshots`. Нова історія зберігається у `operator_report_daily`.
Стара колекція не видаляється автоматично, щоб не робити руйнівну міграцію без підтвердження адміністратора.

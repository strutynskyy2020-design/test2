# TM6 Bonus v105: команди, цілі, магазин і перегляди

## Що змінено

### Команди та демо-дані

- Автоматичне створення команд `Продажі А`, `Продажі B`, `Підтримка B` та `Утримання` вимкнено.
- Автоматичне створення демонстраційних користувачів вимкнено.
- Під час першого запуску v105 одноразова міграція видалить ці старі демонстраційні команди з MongoDB.
- Учасники, які були прикріплені до видалених команд, стануть без команди. Їх потрібно призначити до реальних команд у вкладці **Адмінка → Команди / Юзери**.

### Пароль адміністратора

`ADMIN_PASSWORD` тепер використовується тільки під час першого створення `admin@callhub.ua`. Після зміни пароля в адмінці deployment або перезапуск backend більше не перезаписує його значенням зі змінної середовища.

> MongoDB має бути постійною. Якщо хостинг щоразу створює порожню базу, акаунт буде створений заново з bootstrap-паролем.

### Магазин

- Приз може бути **загальним** або доступним лише одній команді.
- В адмінці у редакторі призу додано поле **Кому доступний приз**.
- Backend додатково перевіряє команду під час купівлі, тому прихований командний приз не можна купити прямим API-запитом.
- У магазині показуються всі категорії: привілеї, мерч, сертифікати й аватари.

### Цілі та рейтинги

- Кредитний і дебетовий рейтинги фільтруються за командою учасника.
- Особисті проєкційні/порівняльні значення беруться з підсумкової колонки саме його команди.
- Адміністратор може дозволити або заборонити перегляд інших команд у **Адмінка → Цілі**.
- Якщо доступ увімкнений, у кредитному та дебетовому рейтингах з’являється селектор команди.
- Зміна команди або політики доступу автоматично оновлює персональний кеш звітів у фоні, навіть якщо Google snapshot не змінювався.

### Повідомлення керівника

На сторінці **Цілі** керівник команди бачить кнопку повідомлення у правому верхньому куті. Текст показується всім учасникам його команди.

### Хто переглянув звіти

Друга маленька кнопка у правому верхньому куті сторінки **Цілі** показує за поточний київський день:

- хто відкривав сторінки цілей/звітів;
- хто відкривав власні кредитні або дебетові показники.

## Підготовка Google Таблиці для кількох команд

Назви команд у застосунку мають містити код `TM1`, `TM6`, `TM7` тощо.

### Рейтинги на `Аркуш2`

Для кожної команди додайте окремий підсумковий рядок у колонці логіна:

- `tm1`
- `tm6`
- `tm7`

Apps Script збере ці рядки у `credit_group_summaries` та `debit_group_summaries`.

### Проєкційні значення на аркуші трансформації

Додайте підсумкові колонки, назви яких закінчуються кодом команди, наприклад:

- `Підсумок TM1`
- `Підсумок TM6`
- `Підсумок TM7`

Якщо для команди немає її підсумкової колонки, застосунок не підставлятиме показники іншої команди.

## Встановлення

1. Розгорніть ZIP-проєкт на Netlify та backend-хостингу.
2. У Google Apps Script замініть `Code.gs` файлом `TM6-Code-v105.gs`.
3. Відкрийте **Deploy → Manage deployments → Edit → New version → Deploy**.
4. Для кнопки в Google Таблиці залиште назву функції `refreshReports`.
5. Натисніть **Оновити звіти** один раз.
6. На телефоні повністю закрийте PWA та відкрийте знову, щоб активувався Service Worker `tm6-v105`.
7. В адмінці створіть реальні команди й призначте учасників.

## Перевірки

- Python syntax/compile для backend.
- JavaScript syntax для Netlify Functions та Apps Script.
- JSX/JavaScript parsing усіх frontend-файлів через TypeScript parser.
- Повну production-збірку React не виконано, оскільки архів не містить `node_modules`, а доступний npm registry не віддає необхідні Babel-пакети.
